# MyBrowser

Локальный браузер с отдельными профилями и управлением через MCP. Основа: **BrowseForge 2.1.15 + Camoufox 156.0.1-beta.36**, Linux x86_64. Chromium сохранён как дополнительный runtime.

В репозитории: исходники менеджера с исправлением SOCKS5 IPv6, обёртки запуска, четыре нативных WebGL-режима, согласованные UA/headers/locale, настройки WebRTC, отключённая симуляция humanize, MCP stdio-мост, прямое подключение к HTTP-прокси в обход локального VPN, шаблоны восьми профилей и обезличенные результаты проверки.

Данные браузеров, cookies, аккаунты, пароли прокси и API-токены хранятся **вне Git**. Приватность репозитория не заменяет это разделение. На этой машине исходная установка BrowseForge продолжает работать независимо от MyBrowser.

Остался **Proxy detected**: тестовый выходной IP классифицирован как hosting/public proxy. Прокси подключался напрямую через физический интерфейс, IP менялся, часовой пояс совпадал. WebGL-хеши двух профилей различались и сохранялись после перезапуска.

Полного прохождения и универсальной нераспознаваемости не заявляем. Четыре режима рендеринга не дают уникальность для неограниченного количества профилей. Softpipe медленный. Результат зависит от оборудования, шрифтов, адреса прокси и версии сканера. [Подробности и доказательства](docs/verification.md).

## Установка

Нужны Linux x86_64, Python 3.11+, Go 1.25+, systemd user session, графический сеанс X11/Xwayland, `ip` из iproute2, библиотеки GTK/NSS/ALSA/Mesa и системные шрифты. Python-зависимостей для наших скриптов нет; Go-зависимости закреплены в `go.mod` / `go.sum`.

```bash
git clone <URL_ВАШЕГО_ПРИВАТНОГО_РЕПОЗИТОРИЯ> MyBrowser
cd MyBrowser
python3 scripts/install.py
./bin/mybrowser seed-profiles
./bin/mybrowser open
```

Установщик собирает менеджер из `vendor/BrowseForge`, скачивает закреплённый Camoufox и проверяет SHA-256. Playwright driver устанавливается штатной командой менеджера. Версии и контрольные суммы: [config/versions.json](config/versions.json).

Данные по умолчанию: `~/.local/share/mybrowser`. Менеджер слушает только `127.0.0.1:19290`, мост прокси — `127.0.0.1:19299`. Службы `mybrowser.service` / `mybrowser-proxy-direct.service` запускаются по требованию, автозапуска при входе нет. Без файла прокси мост пропускается.

Можно переиспользовать уже установленные движки, копируя только их файлы:

```bash
python3 scripts/install.py --reuse-browsers /ПУТЬ/К/BrowseForge-lite/browsers
```

Chromium включается только при наличии `browsers/browseforge-chromium/chrome`. Свежая установка скачивает Camoufox; Chromium автоматически не скачивается. Без Chromium создаются четыре Firefox-профиля, с ним — все восемь. Новые профили можно создавать через панель или MCP без ограничения тремя профилями.

`MYBROWSER_HOME` меняет каталог данных. При его использовании задавайте одинаковое значение установщику и MCP/CLI. Порты задаются при первой установке: `--port` / `--relay-port`. Повторная установка сохраняет существующий `config.json`, профили и настройки; перед обновлением остановите службу. После перемещения репозитория обновите пути обёрток в локальном `config.json` и заново запустите установщик для обновления unit-файлов.

## Управление через MCP

В конфигурации MCP-клиента:

```toml
[mcp_servers.mybrowser]
command = "/АБСОЛЮТНЫЙ/ПУТЬ/MyBrowser/bin/mybrowser-mcp"
```

Для нестандартного каталога данных:

```toml
[mcp_servers.mybrowser.env]
MYBROWSER_HOME = "/АБСОЛЮТНЫЙ/КАТАЛОГ/ДАННЫХ"
```

Токен не нужен в конфигурации клиента: мост читает локальный `data/.api-token`. После добавления сервера перезапустите MCP-клиент. Доступны выбор профиля, открытие/закрытие, навигация, ввод, клики, выполнение JS и скриншоты. Для структурированного результата `evaluate` возвращайте `JSON.stringify(...)`: upstream форматирует обычные JS-объекты как текст. [Контракт инструментов](vendor/BrowseForge/API.md).

```bash
./bin/mybrowser-mcp --call list_profiles
./bin/mybrowser-mcp --call open_browser --arguments '{"profile_id":"prof_ВАШ_ID"}'
./bin/mybrowser-mcp --call navigate --arguments '{"profile_id":"prof_ВАШ_ID","url":"https://example.com"}'
```

## HTTP-прокси и обход VPN

Создайте локальный файл **вне репозитория**, права `0600`, одна строка:

```text
host:port:username:password
```

Допустимы `http://host:port:username:password`, URL с авторизацией и IPv6 в квадратных скобках. Пароль после третьего двоеточия сохраняется целиком. Пример с вымышленными реквизитами: [config/proxy.example.txt](config/proxy.example.txt).

Закройте все окна **MyBrowser** перед сменой общего прокси. Получите ID через `list_profiles`, затем:

```bash
./bin/mybrowser set-proxy --file /ПУТЬ/К/ЛОКАЛЬНОМУ/ФАЙЛУ --direct prof_ID1 prof_ID2
```

Команда копирует файл в закрытый каталог `secrets`, настраивает выбранные Camoufox-профили и перезапускает мост. Реквизиты не выводятся. Без `--direct` профиль подключается к прокси по обычной системной маршрутизации.

Мост пересылает TCP без разбора HTTP и перехвата TLS. Исходящий сокет закрепляется за физическим IPv4-интерфейсом через `SO_BINDTODEVICE` и `bind`; маршрут проверяется. При недоступном физическом маршруте соединение отклоняется. VPN других приложений не меняется. Этот обход проверен с конкретной конфигурацией Hiddify; другие VPN, firewall и права ОС могут помешать ему. DNS имени самого прокси использует системный resolver.

Один мост обслуживает один upstream-прокси. Смена файла требует повторного `set-proxy` для **всех** профилей, использующих этот мост: авторизация профилей должна соответствовать новому серверу. Для разных upstream-прокси одновременно нужны отдельные мосты/порты. Встроенные настройки обычных HTTP/SOCKS5-прокси по профилям доступны через панель/MCP.

WebRTC у настроенных этой командой профилей: `proxy_only`, прямой ICE запрещён; возможен TURN/TCP через прокси. Это ограничивает звонки. У иных прокси-профилей по умолчанию WebRTC отключён. [Параметры профиля](docs/profile-settings.md).

## Разработка и проверка

```bash
make test
make check
git diff --check
```

Локальный smoke test требует **пустого одноразового каталога данных**; сам создаёт профили и открывает браузеры только на локальных fixtures:

```bash
MYBROWSER_HOME="$PWD/.runtime/smoke" python3 scripts/install.py --skip-services --port 19290
MYBROWSER_HOME="$PWD/.runtime/smoke" python3 scripts/smoke.py
```

Не используйте каталог с рабочими профилями для этого теста. Если порт занят, выберите другой при установке.

`make test` проверяет наш парсер/права файлов и пакеты менеджера без публичных антибот-сканов. `make check` проверяет содержимое для Git: приватные каталоги, пути этой машины, известные шаблоны токенов и крупные бинарники. Это дополнительная проверка; просматривайте staged diff перед публикацией.

```bash
./bin/mybrowser stop
./bin/mybrowser start
```

## Приватный GitHub

После просмотра коммита, при установленном и авторизованном GitHub CLI:

```bash
gh repo create MyBrowser --private --source=. --remote=origin --push
```

Либо создайте пустой приватный репозиторий в GitHub, добавьте remote и отправьте `main`. Не добавляйте `secrets`, данные профилей или токены даже в приватный репозиторий.
